# Keep the lead visible and reclaim worker terminals

For TUI, check `HERDR_ENV=1` and verify the target workspace before issuing control commands. The lead and its implementers and reviewers belong to the same verified Herdr workspace. Separate checkouts can live in that workspace. Identify the live lead session before allocating anything: the working directory, a focused tab, or inherited caller IDs alone can point to the wrong task. After creating or moving a pane, read back its workspace, tab, pane ID and occupant.

## Choose where a worker goes

| Situation | Action |
| --- | --- |
| Starting a worker (default) | Keep the lead tab dedicated to the lead. Create a labeled worker tab in the same workspace with `herdr tab create --workspace <ws> --label <task> --cwd <checkout> --no-focus`. Start the first worker in the returned root pane. |
| The user wants to watch one implementation beside the lead | Inspect `herdr pane layout --pane <lead-pane-id>` first. Split only an unzoomed, single-pane tab. As a working default, allow roughly 100 columns and 25 rows for each pane after the split. Use a separate tab whenever wrapping or clipping would still obscure the conversation. Preserve focus. If a second worker arrives, place it in a worker tab. |
| Two workers form a pair worth watching together, such as independent reviewers | Use one labeled worker tab for the pair if both outputs remain legible. Split the worker pane with an explicit target; choose right or down from the actual geometry. For three or more workers, group pairs by task and revision across labeled tabs. Put the odd worker in its own tab. Give each its own tab on a narrow display. |
| A split has made the lead hard to read, or a live worker is in the wrong place | Move only a worker the lead created and still controls. Ask before moving a user-owned or taken-over terminal. Preserve the running session. Use `herdr pane move <worker-pane-id> --new-tab --workspace <ws> --label <task> --no-focus` or move it into an existing owned worker tab. Re-read the returned ID and layout. If user-owned panes occupy the space, leave them in place and ask before moving the lead. |

Split for simultaneous viewing. Use a tab for background work that needs its own screen. When the user requests a lead split, keep at most one worker beside it. Default to two panes at most per worker tab; these are layout defaults, not a reason to cap useful parallel work. Even one split is excessive if the lead's message is unreadable. Prefer an available task-owned shell or reclaim finished workers before adding more tabs. Preserve user focus unless the user asks to see a worker. Tell the user where the worker is when it matters, using a recognizable tab label and its current ID.

## Reclaim as assignments finish

Keep a lightweight record of which tabs and panes the lead created, their session IDs, and the outstanding deliverable. Carry these identifiers into a private handoff only while needed. Treat a pre-existing terminal, the lead tab, or a pane the user took over as user-owned.

- **Keep** a worker while it is running, needs a decision, has uncollected output, holds unaccepted changes, or has a concrete follow-up such as reviewing the repaired revision. On pause, stop new dispatch and record the resume point. Keep in-flight work according to the pause instruction. If the user closes a pane, refresh the inventory, check the execution service for a surviving job, and recover results from the session. Retire the old ID; reopen a terminal only for an agreed need.
- **Reclaim** after collecting an attributable result, preserving useful artifacts or uncommitted work, and either accepting the result or handing its follow-up to a named owner. Before every close, inspect the session, its background jobs and the current occupant. Keep any active job unless its cancellation has been authorized. If the user is viewing the pane, defer cleanup until they leave; unexpected input, a changed occupant or explicit takeover also suspends automated prompts and closure until ownership is clear. Confirm workspace and tab focus: an inactive tab remembers its selected pane. Scroll position alone can reflect the lead reading output. An idle indicator alone does not establish completion. For a replaced or canceled writer, stop its job at the execution service and verify it stopped before allowing another writer into the checkout. Closing a pane alone can leave that job alive.
- **Close the smallest owned unit.** Use `herdr pane close <id>` for a finished pane in a shared tab. For a worker-only tab the lead created, list its members and close it with `herdr tab close <id>` once every occupant meets the cleanup conditions. Never close a whole tab to remove one worker alongside the lead, the user, or another active job. Preserve any session or terminal the user asked to keep.
- **Verify the result.** Re-list the workspace's tabs and panes after cleanup. Confirm the lead is readable, active workers still have their places, and each retained task-owned terminal has a specific reason and next cleanup point. If ownership or live state is unclear, inspect it before acting. Reclaim verified finished terminals without making the user do it.
